각 단계는 구현과 해당 범위의 검증을 마친 뒤 독립된 커밋으로 기록한다. 커밋 제목은 `type: 한국어 변경 내용 요약`으로 작성한다. type은 `feat`, `fix`, `refactor`, `style`, `docs`, `test`, `chore`, `perf`, `remove` 중 선택하고 필요한 검증 결과는 본문에 남긴다. 변경 목적이 다른 작업은 분리하며 로컬 환경변수와 빌드·테스트 산출물은 커밋에서 제외한다.

## 1단계 실행 기반

Next.js App Router와 TypeScript를 구성하고 의존성 버전을 lockfile로 고정한다. `app`, `features/books`, `features/cart`, `components`, `styles`, `lib`의 책임에 맞춰 필요한 파일을 배치한다.

Pretendard와 아이콘·이미지 경로를 연결한다. Vitest·Playwright 설정, 타입 검사·린트·빌드 명령, 환경변수 예시와 ignore 규칙을 준비한다. GitHub·Vercel·Supabase의 프로젝트 연결과 권한을 확인한다.

완료 기준은 최소 페이지 실행과 프로덕션 빌드 성공, 외부 연결에 필요한 설정 확인이다.

## 2단계 디자인 토큰과 정적 화면

Figma의 색상·간격·타이포·이미지 영역을 기준으로 기본 토큰과 의미 토큰을 정의한다. Button, IconButton, TextField, Badge를 만들고 헤더·배너·검색 영역·카드 그리드·페이지 이동·푸터를 조립한다.

헤더 메뉴의 hover·활성 표시와 담기 버튼의 hover·focus 표시를 구현한다. 단품·패스별 공통 이미지를 사용하고 이미지 영역의 비율을 유지한다. 정적 화면에는 개발용 데이터를 사용하며 다음 단계에서 실제 조회로 교체한다.

1440px의 전체 너비·간격·카드 비율·줄바꿈을 비교하고 모바일 배치를 함께 구성한다. 완료 기준은 Pretendard와 토큰을 적용한 주요 화면 영역의 배치 확인이다.

구현된 토큰과 공통 컴포넌트의 책임, 반응형 기준은 [디자인 시스템](design-system.md)에 기록한다. 배너 이미지와 캐러셀 동작은 6단계에서 연결한다.

## 3단계 Supabase와 교재 CSR

migration과 seed를 적용하고 테이블 제약·권한·RLS를 확인한다. 실제 스키마의 DB 타입과 공개용 클라이언트를 구성한다.

`getBooks`에서 DB 응답을 Book으로 변환하고 조회 훅과 UI를 연결한다. 교재는 브라우저에서 요청하며 최초 목록 12개와 전체 개수 18개를 표시한다. 스켈레톤·빈 결과·오류·재시도·이미지 실패 상태를 제공한다. 실제 조회가 연결되면 개발용 데이터의 런타임 사용을 제거한다.

완료 기준은 실제 Supabase 응답과 화면의 상품명·가격·이미지 일치다. Playwright 실제 연결 테스트와 공개 키의 읽기·쓰기 권한 확인을 수행한다.

구현과 검증을 완료했다. 초기 HTML에 상품 데이터가 없고 브라우저가 첫 12개·전체 18개를 조회하는 것을 확인했다. seed 재실행 시 중복이 없으며 공개 키의 추가·수정·삭제 요청은 거부된다. DB 준비·검증 절차는 [README](../README.md)에 기록한다.

## 4단계 검색과 필터와 페이지 이동

검색 입력과 적용 조건을 분리하고 300ms 디바운스 자동 검색·Enter·검색 버튼·X 초기화를 구현한다. 한글 조합이 끝나지 않아도 입력을 멈추면 조회하며 자동 검색은 현재 URL을 교체해 중간값을 이력에 쌓지 않는다. 검색·분류·페이지를 URL에 연결하며 검색·분류 변경 시 새 조건과 1페이지를 함께 반영한다.

조건별 조회 키·요청 취소·정렬·전체 개수·페이지 범위 보정을 연결한다. 늦게 도착한 이전 응답이 현재 조건의 목록을 덮지 않도록 한다.

Vitest로 URL 파싱·정규화·페이지 초기화·가격 계산을 검증한다. Playwright로 검색·분류·페이지 조합, 뒤로 가기, 빈 결과, 잘못된 페이지, 지연 응답·실패 후 재시도를 검증한다. 완료 기준은 전체 12개+6개, 단품 12개, 패스 6개의 결과와 URL이 일치하는 것이다.

구현과 검증을 완료했다. 일반 E2E에서 조건 조합·히스토리 복원·모바일 탐색·요청 취소·실패 후 재시도를 확인했다. 300ms 자동 검색, 한글 조합, 명시적 검색·초기화, 이력 교체, 분류 변경, 입력 공백 보존을 7개 시나리오로 추가 검증했다. 실제 Supabase에서도 Enter 없는 자동 검색, 12개+6개 페이지, 분류별 개수, 괄호·특수문자를 포함한 검색과 416 응답의 페이지 보정을 검증했다.

## 5단계 장바구니

cart에 담기·수량·삭제·비우기와 저장 형식 검증을 구현한다. 같은 상품은 기존 수량만 증가시키고 ID·수량을 localStorage에 저장한다. 최초 복구 전에 빈 상태를 저장하지 않는다.

담기 버튼·토스트·헤더 수량·오른쪽 패널을 연결한다. 수량 조절·개별 삭제·전체 비우기·소계·합계를 제공한다. 모바일 패널, 포커스 관리, Escape 닫기와 트리거 포커스 복귀를 구현한다.

패널을 열 때 ID 목록으로 현재 상품 정보를 조회하고 가격 갱신 중·실패·상품 누락을 구분한다. 현재 목록에 없는 상품도 조회한다.

Vitest로 재담기·수량 경계·삭제·합계·저장 데이터 복구를 검증한다. Playwright로 담기부터 토스트·패널·수량 변경·새로고침 복구까지 연결한다. 임시 프로필을 닫고 다시 열어 보관을 확인하고 가격 변경은 제어된 응답으로 재현한다.

구현과 검증을 완료했다. 전용 Chromium 프로필을 종료한 뒤 같은 프로필로 다시 실행해 상품·수량 복원을 확인했다. 제어된 응답으로 재열기 시 가격 변경·실패 후 재시도·누락 상품을 검증했고, 오프라인·저장 실패·손상 데이터도 구분했다. 실제 Supabase의 ID 조회로 목록 밖 상품과 합계가 일치하는 것을 확인했다. 데스크톱 포커스 순환·닫기 후 복귀와 360·390px 패널의 터치·넘침을 검증했다.

## 6단계 캐러셀과 SEO와 화면 완성

5개 슬라이드의 인덱스·순환 이동·자동 재생·이전/다음·정지/재개를 구현한다. hover·키보드 포커스 시 일시 정지와 동작 줄이기 설정을 적용한다.

서버 제목·설명·canonical·공유 미리보기·robots·sitemap을 구성한다. 상품 CSR을 유지하고 검색·분류 URL과 Preview의 색인 정책을 적용한다.

1440px에서 시안과 세부 간격을 비교하고 390px·360px에서 헤더·검색창·카드·패널의 넘침을 수정한다. Playwright로 캐러셀·메타데이터·키보드·모바일 동작을 검증한다.

구현과 검증을 완료했다. 교재 배경 이미지와 SVG 아이콘을 적용하고 Pretendard·주황색 토큰으로 문구를 구성했다. 동일 이미지의 5초 순환, 실시간 드래그와 좌우 전환·양끝 순환, hover·포커스·명시적 정지·동작 줄이기를 확인했다. 1440px 배치와 768·390·360px의 넘침·터치 조작을 검증했다. 배너는 500·905·1200·2841px에서 배경 영역과 문구·조작부 여백을 확인하고, 전환 중 연속 조작도 검증했다. 터치 스와이프·마우스 드래그·세로 스크롤 구분과 오른쪽 조작부 배치를 확인했다. CTA를 제외한 모든 배너 영역의 드래그 추적과 전환 중 재조작을 검증했다.

서버 HTML의 페이지별 제목·canonical·공유 메타데이터, 검색·분류의 noindex, Native History 이동과 뒤로 가기 후 메타데이터 동기화를 확인했다. 페이지 링크의 새 탭 이동, robots.txt·sitemap.xml 응답도 검증했다. Preview 색인 제외는 단위 테스트로 확인했고 최종 도메인과 Production 배포 응답은 8단계에서 검증했다.

## 7단계 통합 검증

타입 검사, 린트, Vitest, 프로덕션 빌드, 프로덕션 모드 Playwright를 실행한다. 일반 E2E는 제어된 응답으로, 실제 연결 테스트는 Supabase로 실행한다. 실행한 브라우저와 뷰포트를 결과에 기록한다.

검색 조건을 유지한 장바구니 조작, 새로고침, 잘못된 저장 데이터, 네트워크 실패·재시도처럼 기능이 연결되는 지점을 확인한다. 상품 수·가격·이미지가 seed와 일치하는지도 검사한다.

시안과 화면 캡처를 비교하여 정렬·여백·글꼴·이미지 비율을 보정한다. 완료 기준은 기능별 테스트와 통합 흐름의 통과다. 검증 기록에는 실행 명령, 환경, 결과, mock·실제 DB 연결의 범위를 포함한다.

2026-10-19 통합 검증을 완료했다. 린트·타입 검사, Vitest 80개, 제어된 응답을 사용하는 Playwright 53개, 실제 Supabase 연결 5개가 통과했다. 두 E2E 환경의 프로덕션 빌드와 실행도 성공했다. 데스크톱·모바일 목록과 장바구니 캡처를 확인했다. 세부 환경, 재현 명령, 확인한 사용자 흐름과 검증 한계는 [통합 검증 기록](verification.md)에 정리했다.

프로젝트 문서 제목은 `Assignment`로, `package.json`과 lockfile의 패키지명은 `assignment`로 통일했다. 실행·DB 준비·설계·디자인 시스템 문서는 현재 구현과 맞췄다.

## 8단계 배포와 문서화

소스·lockfile·공개 자산·migration·seed·테스트·환경변수 예시를 GitHub에 올린다. Vercel에 Supabase 환경변수와 최종 사이트 주소를 설정하고 배포한다. canonical과 공유 URL에 개발 주소가 남지 않았는지 확인한다.

배포된 주소에서 접근, 실제 교재 조회, 검색·분류·페이지 이동, 장바구니 담기·새로고침 복구, 이미지·폰트 로딩을 검증한다.
